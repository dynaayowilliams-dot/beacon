# Beacon schema v1 (setup)

Network: Tiramisu, 7738577, https://rpc.tiramisu.db-chain.testnet.arkiv.network.
One entity type: `notice`, synthetic data only. No publisher registry or identity attestation yet.

| Attribute | Type | Purpose |
| --- | --- | --- |
| project | str | Namespace `beacon.synthetic.v1` |
| type | str | `notice` |
| notice_id | str | Random UUID for exact proof lookup |
| issued_at | u64 | Numeric Unix seconds for future ranges |

JSON payload: `{ notice: { version, id, publisher, title, body, issuedAt }, signer, signature }`.
The signed message is the fixed-field JSON generated by `noticeMessage` in packages/core, including Beacon domain and chain ID. EIP-191 message signature via viem. Never infer organizational identity from a display name or wallet signature. Compare the immutable entity creator with the signing wallet in this direct-publisher proof. The mutable owner is not provenance.

Entity Expiration: explicitly 168 hours from creation, to cover the stated judging window for a run on 17 October. Entities can expire or be deleted. No Lifetime Extension implemented. Transaction receipts are separate evidence if the live entity disappears.

Exact SDK query used by the write proof (substitute the public receipt's ID and creator):
```ts
client.select()
  .where(eq('project', str('beacon.synthetic.v1')), eq('type', str('notice')))
  .where(eq('notice_id', str(noticeId)))
  .limit(10).createdBy(creator).fetch()
```
The script prints the rendered query and saves a public receipt in `.local/<noticeId>.json`.
Read proof uses namespace and type with limit 10; no ordering or exhaustive listing claimed. Future feed requires cursor pagination (<=200/page) and client sorting. Payload is not queryable.

Questions supported: Can this app query its synthetic notices independently of a Beacon server? Does the exact published payload match the signed message from the creator wallet, and does editing its text invalidate verification?

Arkiv is intended as the primary notice storage and public attribute-query layer, so readers need no publisher-controlled API. Signatures alone could work on other storage; the Arkiv-specific benefit here is independent discovery plus creator metadata and explicit retention. Frontend assets, keys and local tooling stay off Arkiv. A live write and attribute query passed in the builder's normal PowerShell; see connection-proof.json for public identifiers, exact rendered query, and actual expiration block. The agent session could not independently reach RPC.
